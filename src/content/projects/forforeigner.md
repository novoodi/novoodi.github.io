## 풀려던 문제

외국인이 한국의 궁궐이나 음식을 접했을 때 정확한 정보를 얻기 어렵습니다. 일반 LLM에 물어보면 한국 문화 콘텐츠에서는 사실과 다른 내용을 지어내는 일이 잦습니다.

## 구조

전체 서비스는 React 프런트엔드, Spring Boot API, AWS, 그리고 FastAPI로 만든 AI 서버로 이뤄져 있습니다. 저는 이 중 AI 서버 전체를 맡았습니다.

```
이미지 입력
   ▼
YOLOv8 / RT-DETR  객체 탐지
   ▼
궁궐 모델 / 음식 모델  도메인 분류
   ▼
RAG  (FAISS + ko-sbert + Phi-3-Mini)
   ▼
설명 생성 → 사용자에게 반환
```

## 내가 한 일

- **객체 탐지 모델 학습.** AI-Hub 데이터를 정제해 YOLOv8과 RT-DETR을 학습했습니다.
- **한국어 RAG.** LangChain, FAISS, ko-sbert로 검색 파이프라인을 만들고, 도메인별 역할 기반 프롬프트로 LLM이 **검색된 근거 안에서만** 답하도록 제약했습니다.
- **로컬 서빙.** Phi-3-Mini를 GGUF 형식으로 서버에서 직접 구동했습니다.
- **지식 베이스 수집.** 공공 데이터를 한국어, 영어, 일본어, 중국어로 수집하고 정제하는 파이프라인을 만들었습니다.
- **서비스 통합.** 탐지, 분류, 검색, 생성으로 이어지는 흐름을 FastAPI 서버로 묶어 팀의 웹 서비스에 연결했습니다.

## 결과

| 모델 | mAP@0.5 | F1 | 비고 |
|---|---|---|---|
| 궁궐 탐지 (5클래스) | 0.992 | 0.99 | 경복궁, 창덕궁, 창경궁, 덕수궁, 종묘 |
| 한식 탐지 (153클래스) | 0.639 | 0.65 | AI-Hub 한국 음식 데이터셋 |
